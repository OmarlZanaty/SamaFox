Transaction.amountCoins is Int in schema. When logging gift_send the code stores -Number(totalCost). For large gift amounts (yacht = 10000 coins × multiple qty) this could approach Int limits in bulk operations. More importantly, the type mismatch with BigInt arithmetic causes implicit conversions.

MEDIUM No input validation on gift quantity — negative or zero qty possible socket.service.ts

The gift handler uses Math.max(1, Number(quantity || 1)) which prevents 0 but doesn't cap the maximum. A client could send qty=99999 and attempt to buy 99999 gifts in one transaction.

MEDIUM No refresh token rotation — replay attacks possible auth.controller.ts

The refresh token endpoint issues a new token pair but doesn't invalidate the old refresh token. Someone who steals a refresh token can generate new access tokens indefinitely. There is no refresh token blacklist or rotation strategy.

Recommended fix
// Add RefreshToken model to schema: model RefreshToken { id String @id @default(cuid()) userId Int token String @unique expiresAt DateTime revokedAt DateTime? } // On refresh: mark old token as revoked, create new record // On login: create new RefreshToken record // On refresh endpoint: verify token exists and not revoked

Messages routes are mounted twice: app.use('/api/v1/messages', messageRoutes) and app.use('/api/messages', messageRoutes). The second path is unversioned — Flutter may call the wrong one in edge cases, and it creates a security surface for unintended access.

INFO SQLite used in production — will not scale for concurrent gift transactions schema.prisma / .env.example

The schema uses SQLite. For a social app with concurrent gift sending, SQLite's single-writer lock will cause write contention. Prisma $transaction helps but at 50+ concurrent users sending gifts simultaneously, SQLite will serialize all writes and lag. Recommend migrating to PostgreSQL or MySQL before launch.

Migration path
// schema.prisma: datasource db { provider = "postgresql" // change from "sqlite" url = env("DATABASE_URL") } // Then: npx prisma migrate deploy
INFO .env.example has default JWT_SECRET strings — must change before deploy .env.example

JWT_SECRET is "your-super-secret-jwt-key-change-this-in-production". auth.controller.ts correctly throws if JWT_SECRET is missing, but won't throw if someone copies .env.example verbatim. The well-known default value would allow token forgery.

Generate strong secrets for production
node -e "console.log(require('crypto').randomBytes(64).toString('hex'))" // Use the output as JWT_SECRET and JWT_REFRESH_SECRET

Recommendations

Features and improvements to add for a production-ready app

1
Push notifications (Firebase FCM)
Already in .env.example. Add fcmToken to User, call sendPush() for follow/relation/gift events. Background notifications are critical for user retention in a social app.
2
Migrate to PostgreSQL
SQLite single-writer lock will bottleneck concurrent gift transactions. PostgreSQL handles concurrent writes properly and is required for production scale.
3
Redis for seat state persistence
Already in .env.example. Seat state (roomSeats Map) should be stored in Redis so server restarts don't wipe active rooms. Add redis package and replace in-memory Maps.
4
Refresh token rotation + blacklist
Add RefreshToken table. Invalidate old token on each refresh. This prevents stolen token replay attacks and is a security requirement.
5
Image CDN / file upload to S3
Currently uploads go to local /uploads folder. AWS S3 keys are in .env.example but unused. Local uploads are lost on server restarts and don't scale. Connect to S3 or Cloudinary.
6
Global error boundary in Flutter
Add a top-level FlutterError.onError handler and runZonedGuarded() in main() to catch all unhandled exceptions and report to Sentry/Crashlytics rather than crashing silently.
7
API response pagination on room list
Home screen loads all rooms with no pagination. With 100+ rooms this becomes slow. Add cursor-based or offset pagination to GET /rooms with a limit of 20.
8
Room password validation on join
Room schema has passwordHash but the join flow doesn't prompt for or validate passwords for private rooms. Add a password prompt in Flutter when room.type is "private".
9
Gift animation assets — add real images
Gift imageUrls are seeded as /gifts/ward.png etc. but these files don't exist in /uploads. Add real gift images (or animated Lottie files via animationUrl) for each Arabic gift.
10
Add Helmet.js and express-rate-limit to backend
No security headers (Helmet) and no HTTP rate limiting on REST endpoints. Admin login, register, and gift HTTP endpoints are brute-forceable. Add both packages to index.ts.
11
Add notifications tab badge counter
Notifications screen shows follow requests on load but the bottom nav tab has no badge. Track unread count in a Riverpod StateProvider, increment on socket follow_request/relation_request events, clear on screen open.
12
Coin top-up / payment gateway
Stripe is in .env.example but there's no payment route or Flutter payment flow. Users can only receive coins from admin manually. Add an in-app purchase flow or Stripe checkout for coin packages.
13
Add deep links for room sharing
room_screen.dart has a Share button but it just shares a text URL. Add Firebase Dynamic Links or App Links so that opening a shared room link takes the user directly into the room even if the app is not installed.
14
Add account deletion (GDPR compliance)
There is no account deletion endpoint. Required for App Store / Play Store compliance and GDPR. Add DELETE /api/v1/users/me that anonymizes and soft-deletes the account.
15
Add WebSocket reconnection room re-join
When socket reconnects (_onReconnect in socket_service.dart), the app emits the reconnect event but doesn't automatically re-join the current room or re-request the seat snapshot. Users see a blank room after network interruption.
